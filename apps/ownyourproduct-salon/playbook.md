# Build plan: OwnYourProduct Salon

The scaffold you are in is the Chatfuel wizard's engine — its proxy, sign-in, Supabase
project and deploy — with the `auth` and `admin` modules. This plan puts the salon product's
own front on top of it: the product's screens, its Chatfuel client (talking through this
proxy), its records (in this Supabase project), and four server routes mounted in this
proxy. When you finish, the app opens on the product full screen, behind the wizard's
sign-in, with the product's own header and navigation.

Run this whole plan first — before the setup instructions start the dev server for the
owner or say the app is ready. Until step 4 is done the app is the bare shell.

Rules while you work:

- The product front lives in `src/oyp/`. Do not edit it unless the owner asks for a
  product change; everything below is wiring around it.
- Every step ends with a check. Do not start the next step until the check passes.
- Never print keys or tokens from `.env`.

## 1. Bring in the product front

`oyp-front.json` in the app root names the repository and the ref. Fetch it and copy its
`overlay/` directory over the app root. `OYP_FRONT_REPO` and `OYP_FRONT_REF`, when set,
override the file (a local path or a URL, a branch or a tag). Run from the app root:

```sh
set -e
REPO="${OYP_FRONT_REPO:-$(node -p "require('./oyp-front.json').repository")}"
REF="${OYP_FRONT_REF:-$(node -p "require('./oyp-front.json').ref")}"
TMP="$(mktemp -d)"
git clone --depth 1 --branch "$REF" "$REPO" "$TMP/front"
cp -R "$TMP/front/overlay/." .
rm -rf "$TMP"
```

Check: these exist — `src/oyp/App.tsx`, `src/oyp/chatfuel/transport-oleg.ts`,
`src/modules/oyp/index.tsx`, `src/vendor/api/generated/oyp/graphql.ts`,
`vendor/chatfuel-proxy/ownyourproduct.ts`, `supabase/app-migrations/0106_oyp_host_wrappers.sql`.

## 2. Register the module and its operations

The wizard generates both files below, so you edit them by hand:

1. `src/modules/index.ts` — add `import { moduleDescriptor as oyp } from './oyp';` and put
   `oyp` FIRST in `MODULES`. `/` opens the first module of the rail, and an unknown
   path falls back to it.
2. `src/operationDocs.ts` — add `import * as oyp from './vendor/api/generated/oyp/graphql.js';`
   and add `oyp` to the `operations` array. The proxy refuses any operation that is not
   registered here.

Both files are regenerated by `chatfuel-wizard update`; after an update, redo this step.

Check: `npm install` then `npm run check` pass.

## 3. Let the product take the whole screen

The product brings its own header and navigation, so inside the sign-in gate it renders
without the shell's rail and top bar. The sign-in module's own pages (sign-in, Team,
invitations) stay the shell's. In `src/App.tsx`, immediately before
`const shell = (`, add:

```tsx
  /* The product front carries its own navigation, so it takes the whole viewport
     with no rail and no topbar. The auth gate below still wraps it. */
  const standalone =
    !isHostRoute && active.id === 'oyp' && botId ? (
      <div className="min-h-dvh bg-surface font-sans">
        <ErrorBoundary key={`${active.id}:${botId}`} label={active.title}>
          <Suspense fallback={<Spinner />}>
            <active.Component
              key={`${active.id}:${botId}`}
              botId={botId}
              client={client}
              params={route.params}
              setParams={setParams}
              view={view}
              setView={setView}
              navigate={navigate}
              installedModules={MODULE_IDS}
              selectBot={selectBot}
            />
          </Suspense>
        </ErrorBoundary>
      </div>
    ) : null;
```

and change the final `return` so it renders `standalone ?? shell` in both branches:

```tsx
  const content = standalone ?? shell;
  return host ? (
    <host.Gate route={route} navigate={navigate}>
      {content}
    </host.Gate>
  ) : (
    content
  );
```

Check: `npm run check` passes.

## 4. Mount the product's server routes

`vendor/chatfuel-proxy/ownyourproduct.ts` serves provider access, the Instagram channel
link, staff invitations and price import behind the same gate as everything else. In
`vendor/chatfuel-proxy/core.ts`:

1. with the other local imports add
   `import { handleOwnYourProduct, isOwnYourProductRoute } from './ownyourproduct.js';`
   (the `.js` extension matters — the files are transpiled one by one on Vercel);
2. in `matchRoute`, after the publishing-queue block and before `return null`, add:

```ts
    // OwnYourProduct's own routes: same mount condition as the publish queue.
    if (config.publishingQueueRoute && isOwnYourProductRoute(pathname)) {
      return (req, res) => settle(res, handleOwnYourProduct(ctx, req, res, pathname));
    }
```

Check: `npm run check` passes; with `npm run dev` running, the startup line says
`publish queue routes mounted` (if it does not, `SUPABASE_SERVICE_ROLE_KEY` is missing from
`.env` — the routes need it), and a request without a session is refused by the gate:

```sh
curl -s -o /dev/null -w '%{http_code}\n' -X POST localhost:5173/chatfuel/team/invite \
  -H 'content-type: application/json' -d '{}'
```

prints `401`, not `404`.

## 5. Choose the surfaces

The owner's message says which modules they chose, as a line `VITE_SKU=…`:
`agenda` is the calendar alone, `agenda+ig` the calendar and Instagram. Set that value in
`.env` as `VITE_SKU=…`. If the message has no such line, use `agenda+ig`. Restart
`npm run dev` after changing `.env`.

Check: `grep -c '^VITE_SKU=' .env` prints `1`. The switcher itself is checked in step 7,
once somebody is signed in.

## 6. Create the product's tables

Apply, in name order, after the wizard's own `supabase/migrations` (the wizard applied those
when it set the project up): `supabase/app-migrations/0019_staff_access.sql`, then
`0101_oyp_tenant_persistence.sql` … `0106_oyp_host_wrappers.sql`. Either paste each file in
the Supabase SQL editor (`https://supabase.com/dashboard/project/<SUPABASE_PROJECT_REF>/sql`),
or, with a Supabase access token in `SUPABASE_ACCESS_TOKEN`, send each file to
`POST https://api.supabase.com/v1/projects/<SUPABASE_PROJECT_REF>/database/query` as
`{"query": <file contents>}`. If a file fails because its objects already exist, the
project already has it: check with the queries below and move on.

Check, in the SQL editor: `select to_regclass('public.cf_agenda_records')` is not null, and
`select count(*) from pg_proc where proname like 'cf_oyp_%'` returns 7.

## 7. Walk it as the owner

With `npm run dev` running: sign up with a fresh e-mail on `http://localhost:5173/`. The
wizard's sign-up creates the owner's workspace and bot; the app opens on the product.

Check, in this order:

1. Set-up (five steps) publishes the salon; the calendar opens.
2. The booking window (`+`) books an appointment for a new client and says
   "It's in your calendar"; the booking is in the Chatfuel dashboard for this bot.
3. Settings → reports PIN: set one, then Reports asks for it and accepts it.
4. With `agenda+ig`, the header shows the switcher (Agenda · Instagram in Spanish and
   Portuguese, Calendar · Instagram in English) and Instagram → connect opens a
   `panel.chatfuel.com` link. With `agenda`, there is no switcher and no Instagram tab.
5. `/team` opens the shell's Team page, and the product's sign-out button signs out of the
   app (the next load shows the sign-in).

## 8. Put it online

The wizard does not deploy. `npm run deploy` puts the app on Vercel through the Vercel
CLI (a Vercel login is asked once). Then in Supabase, Authentication → URL configuration,
add the production origin to the redirect allowlist. If the Vercel team has Deployment
Protection on, turn it off for this project, or the salon's staff meet a Vercel login.

Check: the production URL opens the sign-in; signing in lands on the product.

## Out of scope

- Ads (`VITE_SKU` with `+ads`): needs the Meta OAuth server routes, not in this package.
- WhatsApp reminders (subflow): need a server-held key; Settings says they are not
  available in this installation.
- The product's operator panel: the wizard's `admin` module is the operator panel here.
- Moving an existing salon's data from another installation.
